# Читання новин у застосунку

## Реалізація

- `GET /api/city-services/news/article?url=…` зберігає попередні `title`, `sourceUrl`, `publishedLabel`, `preview` і додає `blocks`, `links`, `imageUrl`, `fullTextAvailable`.
- Парсер бере лише `.post-item-inner-content` усередині `<article>` на офіційному сайті. Структуру перевірено на публікації міськради «Книга-фест» 09.10.2026. Вкладені div обробляються до відповідного закривального тегу.
- Повний текст не має колишнього обмеження 720 символів. Воно лишається тільки для сумісного короткого `preview`.
- Абзаци, підзаголовки, списки, переноси рядків та HTML entities перетворюються на звичайний текст. HTML/скрипти не виконуються на телефоні; меню та бокові панелі не додаються до статті.
- Посилання з тексту доступні окремими діями. Фото дозволені з офіційного домену, їхні пропорції зберігаються; недоступне фото не блокує читання.
- Дата береться зі статті, якщо вона є. Читач показує її як «8 жовтня 2026». Новина без дати більше не запозичує дату наступного заголовка у списку.
- Якщо змінилася структура сайту, відповів старий сервер або немає тексту, екран показує «Коротко» і пояснює, що це не повна публікація. Кнопка оригіналу лишається доступною навіть після помилки.
- Читач винесено з App.tsx. Є повтор запиту, захист від застарілих відповідей і оновлення стану після виходу. Дві теми використовують спільну civic-палітру.

## Перевірки

```powershell
cd C:\Users\bahen\IdeaProjects\uzhhorod-app\mobile
npm run release:check

cd C:\Users\bahen\IdeaProjects\uzhhorod-app\backend
.\mvnw.cmd "-Dtest=OfficialNewsParserTest" test
```

Для середовища без завантаженого Spring parent є вузька альтернативна перевірка `backend/scripts/check-news.ps1`: вона компілює парсер та виконує його JUnit-методи з локальних кешованих бібліотек. Це **не** повна Spring/Maven-збірка. У поточній Windows-пісочниці javac повідомляє AccessDeniedException під час закриття ZIP-кешу після компіляції; виконання восьми тестів перевірене окремо, а повна збірка залишається непідтвердженою.

`scripts/news-preview-entry.tsx` і `scripts/news-preview-server.mjs` — ізольований браузерний QA, не екрани застосунку. Він використовує реальний NewsArticleScreen і JSON, згенерований Java-парсером із тестового знімка офіційної статті. Не змінює `.env`, базу або робочий сервер. Перевірено світлу/темну тему, вузьку ширину, фото й останній абзац. Скріншоти: `output/news-reader-qa/`. Нативний VoiceOver, Dynamic Type та safe-area ще треба перевірити на телефоні.

На ширинах 390 і 320 px немає горизонтального переповнення. Дата на реальному DOM: світла `rgb(91,107,124)` на `rgb(246,247,251)` — **5,11:1**; темна `rgb(169,190,211)` на `rgb(7,27,47)` — **9,11:1**. Кнопка повернення закриває читач; останній абзац і посилання на оригінал доступні внизу прокрутки.

## Важливо для запуску

На момент перевірки робочий API `192.168.1.5:8080` ще повертав лише старі чотири поля. Повний читач увімкнеться після **збирання та перезапуску бекенду з новим кодом**. Оновлення тільки Expo недостатньо. До цього застосунок чесно показуватиме «Коротко».

У цій сесії повна Maven-збірка недоступна: у кеші немає `spring-boot-starter-parent:3.5.16`, зовнішнє завантаження обмежене. Версію Spring не змінювали. Після звичайної збірки в IDE/терміналі перевірити, що `/article` повертає `fullTextAvailable: true` та непорожні `blocks` для зазначеної статті, а потім відкрити її з головної та стрічки на телефоні.
