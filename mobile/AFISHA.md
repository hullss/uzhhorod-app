## Редагування та сервер

Файл мобільної резервної добірки: `src/events/verified-events.json`.
Серверна копія: `backend/src/main/resources/editorial/events.json`. Тест check:events контролює їхню однаковість. Після зміни резервної добірки оновити обидва файли.

GET `/api/editorial/events` використовує документ з БД. Лише коли документа взагалі немає, повертає упаковану добірку; порожній документ з БД не замінює і дані редактора не перезаписує. Потрібно перезапустити бекенд з новим кодом, щоб він використовував ці правила.

Редакторське оновлення: PUT `/api/admin/editorial/events`, заголовок X-Admin-Key (ключ налаштовується на сервері, не в мобільному застосунку). Тіло `{ "items": [...] }`. Обовʼязкові: id, title, date YYYY-MM-DD, category (9 категорій із src/events/catalog.ts), venue, description, sourceUrl HTTPS, verifiedAt YYYY-MM-DD. Додаткові: time HH:mm, address, posterUrl HTTPS, organizer. Сервер відхиляє неможливі дати, дублікати, небезпечні посилання. Перед збереженням звірити саме місто, рік та конкретну подію у джерелі.

Це редакторська добірка, не автоматичний парсер продавців. Оновлення екрана завантажує останні опубліковані редактором дані, а не сканує весь інтернет. При недоступній мережі мобільний застосунок чітко позначає збережену добірку; зображення без мережі можуть бути недоступні.

### Виконана перевірка

- release:check пройшов після остаточних змін (TypeScript, контраст, оплата, стабільність, layout, ЦНАП/опитування та афіша).
- Браузер: 390×844 та 320×740, картки/довгі назви без горизонтального переповнення, фільтр Інше з порожнім майбутнім списком, архів у зворотному порядку, внутрішні деталі, кнопка Сторінка події для архіву, інформаційна панель та повернення.
- У деталях виміряно кнопки 48 px, адресний перехід 44 px, основну дію 52 px. Постери завантажуються; два архівні записи без підтвердженого зображення показують іконку в списку, без порожнього hero в деталях.
- API з поточної конфігурації у браузері недоступний: перевірено стан помилки зі збереженою добіркою. Успішний порожній список та захист від запізнілих відповідей перевірені автоматично, не на живому сервері.
- Maven wrapper спробував завантажити дистрибутив і не зміг через мережеві обмеження. Наявний локальний Maven в offline-режимі також зупинився: немає Spring Boot parent 3.5.16 у кеші. JUnit-тести додані, але їхнє проходження та серверна компіляція не підтверджені.
- Дві палітри перевірені обчисленням контрасту спільних civic-кольорів. Візуальний прохід виконано у світлій темі; темна тема на iPhone і нативна доступність ще потребують ручного тесту.

### Виправлення порожньої афіші на живому сервері

Після повідомлення користувача перевірено поточний API з `mobile/.env` (`http://192.168.1.5:8080/api/editorial/events`) і localhost: обидва повертали items:[]. Read-only перевірка саме таблиці editorial_documents встановила відсутність документа events, а не навмисно очищений список. Опубліковано перевірені 8 подій одним INSERT … ON CONFLICT DO NOTHING, без перезапису наявних документів і без зміни інших таблиць. Повторний GET за адресою, яку використовує телефон, підтвердив 8 записів із правильними українськими назвами, повними датами й часом. На 8/9 жовтня це 4 майбутні та 4 архівні події. Перезапуск для цього наповнення не потрібен; для застосування нового серверного валідатора код бекенду все ще потрібно перезібрати/перезапустити.
