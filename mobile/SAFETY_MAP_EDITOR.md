# Редактор укриттів і пунктів незламності — 9 жовтня 2026

## Зроблено

- У тій самій адмінці два нові розділи зі звичайними формами: назва, адреса, широта/довгота, опис входу, джерело, дата фактичної перевірки.
- Додавання, редагування, пошук за назвою/адресою, вилучення з чернетки й окрема публікація з діалогом усередині сторінки. Початковий список обов’язково завантажується; ID зберігається при редагуванні.
- Дані публікуються в наявній таблиці editorial_documents. Нові схеми/міграції та новий адмін-ключ не потрібні.
- Після першої публікації редакторський список повністю замінює автоматичне джерело саме цього розділу. Автоматичні правки джерела не перетирають адреси. Навіть порожній опублікований список має пріоритет. Два переліки незалежні.
- Існуючі API `/api/city-services/maps/shelters` і `/resilience` читають опубліковані точки без TTL геопорталу. Мобільний застосунок отримує їх при відкритті/оновленні карти. Натискання на мітку показує адресу, опис, дату й посилання.
- У редакторському режимі старий растровий шар укриттів вимикається: видалена точка не лишається намальованою на тайлах. Базова карта та власні маркери залишаються.
- Сервер/форма перевіряють обов’язкові поля, унікальні ID, координати в межах Ужгорода, HTTPS-джерела, справжні/не майбутні дати. Кома в координатах приймається. Дата перевірки не підставляється автоматично. Застереження про актуальність доступу не приховане.
- Нові підписи застосунку перекладено англійською; самі редакторські адреси/описи не перекладаються автоматично.

## Перевірено

- `npm run release:check`: TypeScript та всі регресійні перевірки; новий `check:safety` перевіряє форму/декодер, порожні списки, дублікати, координати, метадані й небезпечні посилання.
- `backend/scripts/SafetyMapCheck.java`: справжні EditorialController, EditorialSafetyMapStore і SafetyMapPointService з in-memory репозиторієм та ізольованим loopback GeoJSON. Пройдено імпорт без запису, публікацію/читання, адресу/координати/опис, стабільний ID, незалежність списків, видалення всіх точок без повернення з кешу, невалідні запити та неправильний ключ.
- Компіляція змінених Java-класів із кешованими залежностями успішна; javac повідомляє AccessDeniedException при закритті ZIP-файлу, але повертає 0 та виконувані перевірки проходять. Це не повний Spring/JPA/реальний PostgreSQL інтеграційний тест.
- Повний Maven-тест не запустився: wrapper намагається завантажити Maven, а мережеве з’єднання недоступне. Налаштування безпеки й версію Spring не змінювали.
- Браузер: справжні файли адмінки на ізольованому API. Виправлення укриття, координата з комою, публікація й повторне завантаження; додавання пункту з порожнього списку; помилка переплутаних координат; скасування публікації зберігає чернетку; новий діалог працює без стандартного confirm. Скріншот: output/safety-admin-qa/editor-form.png.

## Запуск і межі

Перезберіть/перезапустіть бекенд, налаштуйте EDITORIAL_ADMIN_KEY (якщо ще не задано) і відкрийте http://localhost:8080/admin/index.html. Повна інструкція — backend/EDITORIAL_ADMIN.md.

Реальні точки, адреси та об’єкти в БД цього проходу не додавались. Фіктивні QA-точки жили лише в пам’яті ізольованого процесу й не потрапили до застосунку. Після публікації власного каталогу його підтримка ручна; історії редакторських версій/захисту від одночасного перезапису ще немає. При недоступному геопорталі початковий імпорт показує помилку, не порожній список. Фізичний iPhone, нативні мітки й реальна БД після перезапуску сервера потребують окремого smoke-тесту.
