# Світло за адресою

Відкрити: **Сервіси → Світло за адресою** або **Профіль → Моя адреса**. Вибрати населений пункт і вулицю з довідника оператора, ввести будинок, зберегти. Зміна й видалення працюють без акаунта. Збережена адреса відновлюється після перезапуску.

Адреса лише на цьому пристрої: SecureStore на телефоні, localStorage у веб-прев’ю. Синхронізації адреси з акаунтом немає. Сервер отримує місто, вулицю й будинок для перевірки, але не записує їх у БД. До джерела надсилає лише ID міста/вулиці, зіставлення будинку локальне. Не вводьте квартиру, особовий рахунок або інші персональні дані. Не включайте query strings цих запитів до access/analytics logs на reverse proxy.

Джерело: <https://zakarpat.energy/customers/break-in-electricity-supply/realtime-outage/>. Сторінка вбудовує <https://outage.zakarpat.energy/>, чий публічний код звертається до `https://api-outage-zakarpat-energy.inneti.net/api`. Це не задокументований партнерський контракт і може змінитися. Ключ API/покупка не потрібні для поточного read-only адаптера; перед публічним розгортанням погодити використання, ліміти й правила з оператором.

## Що показуємо

- Поточні записи `pw_accidents` (аварійні, планові та графікові), майбутні/незавершені планові роботи `pw_accident_planeds`.
- Точне зіставлення номерів, а не `contains`: будинок 1 не збігається з 10; 19А та 19A зіставляються. Нестандартні переліки й діапазони не вгадуємо.
- Черга ГПВ з `pw_address_queues` — не прогноз фактичного погодинного вимкнення. Окремий календар ГПВ не імпортується.
- Причина, початок, орієнтовне відновлення, час перевірки кешу й час успішної синхронізації джерела.
- Якщо будинок не підтверджений, дані джерела старші 24 годин, майбутня дата некоректна, перелік неоднозначний або прогноз відновлення поточного запису минув — не кажемо, що відключень немає.
- Навіть успішне «За даними оператора відключень не знайдено» не гарантує наявності світла. Кнопка офіційного джерела завжди доступна.

Оновлення кожні 5 хвилин тільки на відкритому екрані та коли застосунок активний; також при поверненні з фону та вручну. Після виходу таймер і слухач прибираються, запізнілі відповіді ігноруються. Немає фонового моніторингу, push, SMS чи обіцянки миттєвої доставки.

## Сервер

Після змін **перезібрати й перезапустити бекенд** (у IntelliJ Stop → Run), оновити застосунок у Expo. Не запускайте другий сервер на зайнятому 8080.

- `GET /api/city-services/power/cities`
- `GET /api/city-services/power/streets?cityId=769`
- `GET /api/city-services/power/status?cityId=769&streetId=9479&building=1`

Опційний `POWER_OUTAGE_API_URL` у backend/.env; значення за замовчуванням вже налаштоване. Довідник кешується на 12 годин, групи адрес — 6 годин, відключення/синхронізація — 3 хвилини. Кеш обмежений 256 запитами, upstream URL не задається клієнтом, зовнішні pagination URL не виконуються. Помилка/неповна відповідь — 503, не порожній «успіх».

## Перевірки

`npm run release:check` у mobile включає check:power. Java `PowerOutageServiceTest` — ізольовані HTTP fixtures. `PowerOutageLiveTest` запускається лише явно з `-Dpower.live=true`; не піднімає Spring/БД і читає лише публічне джерело.

UI fixtures: Expo Metro на 8084, `node scripts/power-preview-server.mjs`, відкрити <http://localhost:8092>. Не входить до production App; має окремий origin і тестові відповіді. Це перевірка компонента, не доказ актуальності реальних відключень. На фізичному iPhone ще перевірити клавіатуру, safe area, великі шрифти й VoiceOver.

Під час перевірки 09.10.2026 `release:check`, три ізольовані тести power і opt-in запит реального джерела пройшли. Повний `mvn test` зупиняється на раніше створеній V9: H2 не підтримує дві `add column` через кому в одному `alter table`. PostgreSQL-міграцію й користувацьку БД не змінювали; це окрема задача сумісності тестового середовища.

Пункти незламності приховані лише в списку сервісів; мапа, API й редактор не видалені. Укриття залишені з попередженням, що мітка не підтверджує відкритий вхід.
