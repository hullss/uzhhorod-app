# Готовність до показу «Ужгород Цифровий»

Перевірки нижче — критерії приймання, а не твердження, що все вже протестовано на iPhone.

## Порядок підготовки

1. У `mobile`: `npx expo install expo-camera`, потім `npm run release:check`.
2. Запустити PostgreSQL і backend. Для фізичного телефона в `.env` має бути доступний IP ноутбука.
3. Університетський Wi-Fi може блокувати локальний API. Надійний локальний сценарій — власний хот-спот; Expo tunnel сам по собі не відкриває backend.
4. Перезапустити Expo: `npx expo start -c`. Перед показом перевірити джерела погоди, новин і GPS: наявність коду не гарантує, що зовнішній сервіс відповідає.
5. Зберегти коротке відео успішного проходу як запасний матеріал, але не видавати запис за поточний live-сценарій.

## Сценарій на 5 хвилин

Головна → остання новина → назад → Сервіси → транспорт → маршрут → карта → зупинка → назад → тестова оплата держномером/QR → квиток → карта укриттів → адреса точки.

Акаунт, налаштування й афішу показувати окремо, якщо є час. ЦНАП, платежі та опитування позначати як демонстраційні сценарії; не обіцяти місту вже підключену обробку заяв чи грошей.

## Матриця фізичного телефона — перевірити вручну

Для кожного екрана: світла/темна тема; звичайний/збільшений системний шрифт; довгі українські назви; клавіатура; VoiceOver; натискання дрібних кнопок; повернення свайпом і кнопкою.

- [ ] Головна: погода/повітря/тривога поруч; не обрізані підписи; pull-to-refresh завершується після всіх трьох блоків.
- [ ] Новини: саме останні три на головній; стаття не підміняється попередньою; стрічка оновлюється жестом і показує додаткові новини всередині застосунку.
- [ ] Транспорт: швидко змінити пошук/тип списку; попередня відповідь не повертає старі результати. При зависанні є повернення; retry повторює потрібний запит.
- [ ] Карта маршруту: збережені автобуси та стрілки; контрастна лінія в обох темах; перемикання напрямку; швидке натискання різних зупинок не змішує розклади.
- [ ] Дати/рейси: час міста Europe/Kyiv, навіть коли телефон у Словаччині/Угорщині; перевірити межу доби.
- [ ] Без мережі: вхід не зникає після перезапуску; запит завершується повідомленням; старий CLEAR не показується як актуальний відбій; GPS не лишається «живим».
- [ ] Акаунт: повторний email, хибний пароль, повтор пароля, подвійне натискання, вихід; видалення підтверджується лише після успішної відповіді сервера. Не видаляти особистий акаунт заради тесту — використати окремий тестовий.
- [ ] Сповіщення: змінити категорії → закрити → відкрити → перезапустити. Для акаунта перевірити синхронізацію з backend; для гостя — локальне збереження.
- [ ] Оплата: ручний номер, камера, відмова дозволу, повторна спроба, довільний QR, пасажири 1–5, скасування обробки, відновлення історії. Не вводити реальні карткові дані.
- [ ] Укриття/незламність: мітка → повна адреса → зовнішній маршрут. Звірити координати й адреси з офіційним джерелом, не підміняти невідому адресу вигаданою.
- [ ] Події: дати й сторінки продавців актуальні саме на день показу; архівні події не представляти як майбутні.
- [ ] ЦНАП/опитування/паркування: зрозуміла дія й повернення; немає неправдивого підтвердження реальної операції.

## Автоматичні перевірки

`release:check` об’єднує TypeScript, вибрані контрастні пари, логіку демонстраційної оплати й перевірки мережі/акаунта/сховища/часового поясу.

Це не заміна перевірки нативної камери, карти, VoiceOver чи повного візуального аудиту. На 8 жовтня 2026 в агентському середовищі встановлення `expo-camera` та завантаження Maven заблоковані мережею; повна збірка й backend-тести потребують запуску у звичайному терміналі розробника.

## Що не готове до production

Реальні push і платежі, обробка звернень ЦНАПом, повний переклад English, доставлення email для відновлення/верифікації, постійний HTTPS backend та погодження офіційного статусу. Зустріч із кластером не вимагає видавати ці інтеграції за вже виконані.
