# Ужгород Цифровий

## Локальний запуск бекенду

Потрібні Docker Desktop і Java 21. Maven окремо не потрібен: перший запуск `mvnw.cmd` завантажить Maven Wrapper.

```powershell
docker-compose up -d
cd backend
.\mvnw.cmd test
.\mvnw.cmd spring-boot:run
```

PostgreSQL буде доступний на `localhost:5432` з базою `uzhhorod_digital` та обліковими даними `postgres` / `postgres`. Це відповідає локальним значенням у `backend/src/main/resources/application.yml`.

## Перевірка транспорту

У другому PowerShell-вікні:

```powershell
Invoke-RestMethod -Method Post http://localhost:8080/api/transport/imports/gtfs
Invoke-RestMethod http://localhost:8080/api/transport/routes
Invoke-RestMethod "http://localhost:8080/api/transport/vehicles?routeNumber=2"
```

Перший запит завантажує статичні GTFS-дані Ужгорода й записує маршрути, зупинки, розклад і геометрію маршрутів у PostgreSQL. Далі бекенд оновлює дані щодня о 03:00 за Ужгородським часом, якщо він у цей момент запущений.

Статус останнього успішного імпорту:

```powershell
Invoke-RestMethod http://localhost:8080/api/transport/imports/latest
```

Для локальної розробки ручний імпорт не потребує токена. У розгорнутому застосунку встановіть змінну середовища `TRANSPORT_IMPORT_TOKEN`; тоді для ручного імпорту передавайте цей самий токен у заголовку `X-Transport-Import-Token`.

## Джерела транспортних даних

Маршрути, зупинки, розклад і геометрія маршрутів завантажуються з GTFS-джерела Ужгорода. Дані у застосунку мають містити посилання на першоджерело та ліцензію CC BY 4.0.

На карті маршруту також доступні живі GPS-позиції з публічного DozoR-ресурсу, який оприлюднює Відділ транспорту. Бекенд оновлює відповідь не частіше ніж раз на 20 секунд для обраного маршруту й віддає `available: false`, якщо джерело тимчасово недоступне. Технічні ідентифікатори трекерів до API не потрапляють.

GPS-маркери не є прогнозом прибуття: час на зупинці в застосунку залишається плановим GTFS-розкладом. Перед демонстрацією перевірте конкретний маршрут через `GET /api/transport/vehicles?routeNumber=...`; нуль автобусів означає, що на цьому маршруті в момент запиту позицій не було, а не помилку в розкладі.

## Мобільний клієнт

Відкрийте новий PowerShell у корені проєкту й виконайте:

```powershell
cd mobile
Remove-Item node_modules -Recurse -Force -ErrorAction SilentlyContinue
npm install
npx expo install expo-secure-store
npm run typecheck
npm start
```

Expo покаже QR-код. Відскануйте його через Expo Go на телефоні або натисніть `a` для Android-емулятора.

Для підготовки підписаної Android/iOS release-збірки дивіться [`mobile/RELEASE.md`](mobile/RELEASE.md). Вона навмисно не містить чужих ключів підпису, ідентифікаторів магазинів чи облікових даних.

Для демонстраційного редактора подій і перевірених зборів дивіться [`backend/EDITORIAL_ADMIN.md`](backend/EDITORIAL_ADMIN.md). Сценарій push-сповіщень і необхідні зовнішні налаштування описані у [`backend/PUSH_NOTIFICATIONS.md`](backend/PUSH_NOTIFICATIONS.md).

За замовчуванням клієнт звертається до `http://10.0.2.2:8080`, що працює для Android-емулятора. Для фізичного телефона створіть файл `mobile/.env` на основі `mobile/.env.example` і замініть адресу на локальну IPv4-адресу вашого комп'ютера, наприклад `http://192.168.1.25:8080`.

## Короткий чекліст перед демо

1. Запустіть PostgreSQL та API, виконайте ручний GTFS-імпорт і переконайтеся, що `/api/transport/imports/latest` має `available: true`.
2. Перевірте `/api/transport/vehicles?routeNumber=...` для маршруту, який плануєте показувати. Не обіцяйте живі маркери, якщо джерело відповідає `available: false`.
3. У `mobile/.env` вкажіть IP комп'ютера в тій самій Wi-Fi мережі для фізичного телефона; `10.0.2.2` працює лише в Android-емуляторі.
4. Перед показом запустіть `npm run typecheck`. Погода й повітряна тривога потребують окремих ключів у `backend/.env`; без них екран має показувати коректний стан недоступності, а не тестові дані.

## Міські сервіси: перший MVP

Стартовий екран мобільного застосунку — окремий хаб «Міські сервіси». Його завдання — зібрати зрозумілі точки входу, не видаючи довідкову інформацію за оперативну чи офіційно підтверджену.

Нижня навігація має чотири розділи: **Головна**, **Сервіси**, **Новини** та **Профіль**. У «Новинах» картка відкриває короткий атрибутований перегляд у застосунку, а повний текст — на офіційному сайті міської ради. Там само показується поточний статус повітряної тривоги для Закарпаття, коли джерело доступне. «Профіль» у MVP не вимагає реєстрації й пояснює підхід до персональних даних.

| Картка | Що доступно в MVP | Джерело / межа функції |
| --- | --- | --- |
| Громадський транспорт | Маршрути, зупинки, плановий розклад і карта | Імпортовані GTFS-дані міста, як і раніше |
| Події й оголошення | Явний перехід до новин і анонсів | Офіційний сайт Ужгородської міської ради |
| Доступне місто | Явний перехід до набору перевірок доступності будівель | Портал відкритих даних міської ради, CC BY 4.0 |
| Паркування | Явний перехід до сервісу інспекторів і пошуку постанов | Офіційний портал ПДР міської ради; без оплати в застосунку |
| Запис до ЦНАП | Наочна чернетка звернення та сценарій майбутньої інтеграції | Демо: дані не надсилаються й не зберігаються; для реальної послуги відкривається офіційний кабінет |
| Підтримка захисників | Банер та окремий екран з постійною Банкою mono | «Рух підтримки закарпатських військових»; застосунок не приймає кошти й лише відкриває офіційне посилання |
| Хвилина мовчання | Спокійна картка про щоденну хвилину мовчання о 09:00 | Лише індикація на екрані, без push-сповіщень |

У цьому етапі застосунок не приймає платежі, не показує штрафи чи персональні дані та не створює екстрених push-сповіщень. Наступним окремим етапом можна підключати дані про парковки й детальніші показники доступності лише після перевірки стабільності схем, частоти оновлення та ліцензії кожного ресурсу.

### Пошук «Доступне місто»

Застосунок отримує через офіційний API перелік будівель, щодо яких Ужгородська міська рада проводила перевірку або моніторинг доступності. Можна шукати за назвою й адресою; для кожного запису показано дату моніторингу. Це **не** є гарантією доступності конкретної послуги, входу або маршруту — перевіряйте деталі на порталі першоджерела.

Бекенд кешує відповідь до шести годин. За потреби змініть `ACCESSIBILITY_DATASTORE_URL` або `ACCESSIBILITY_CACHE_DURATION`, не змінюючи код.

### Оновлення відкритих даних

`GET /api/city-services/open-data/datasets` повертає до 12 останніх змінених наборів із офіційного каталогу відкритих даних. Мобільний клієнт показує лише назву, короткий опис, дату оновлення та посилання на сторінку набору; самі файли й повний вміст залишаються на порталі міської ради. Відповідь кешується на 15 хвилин, а попередня версія віддається з позначкою `stale`, якщо джерело тимчасово недоступне.

За потреби змініть `OPEN_DATA_CATALOG_API_URL`, `OPEN_DATA_CATALOG_URL` або `OPEN_DATA_CATALOG_CACHE_DURATION` без зміни коду.

Станом на вересень 2026 ресурс `parkingLots` у міському наборі даних про паркування позначено як такий, що проходить модерацію. Тому MVP навмисно не показує карту, вільні місця чи тарифи: це могло б вводити водіїв в оману. Коли ресурс стане стабільно доступним, наступним кроком буде імпорт майданчиків та операторів із зазначенням дати оновлення і посиланням на джерело.

Екран «Паркування» вже містить окремі переходи до офіційного пошуку постанови, інструкції на випадок евакуації та контактів інспекторів. Номери авто, платежі й персональні дані не вводяться й не передаються через застосунок.
