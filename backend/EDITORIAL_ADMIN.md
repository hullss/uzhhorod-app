# Редактор контенту для демонстрації

Редактор доступний за адресою `http://localhost:8080/admin/index.html`, коли запущений бекенд. Після збірки поточного коду також працюють `/admin` та `/admin/`. Опубліковані події, перевірені збори, укриття та пункти незламності зберігаються у PostgreSQL, а мобільний застосунок читає їх через API.

## Увімкнення

Додайте до `backend/.env` довгий випадковий ключ, який не передаєте у чатах та не комітите:

```properties
EDITORIAL_ADMIN_KEY=власний-дуже-довгий-випадковий-ключ
```

Після збірки й перезапуску бекенду відкрийте `/admin/index.html`, введіть ключ та виберіть розділ.

### Події міста — звичайна форма

1. Натисніть «Завантажити дані». Це обов’язково: новий список не має випадково замінити опубліковані записи порожнім документом.
2. Натисніть «Додати подію» або «Редагувати» біля наявної. Заповніть назву, дату з роком, час за Києвом, категорію, місце, адресу, опис, пряме HTTPS-посилання й дату перевірки. Постер та організатор необов’язкові.
3. «Додати до списку змін» змінює лише чернетку на екрані. При редагуванні зберігаються id і додаткові поля.
4. «Опублікувати зміни» після підтвердження зберігає весь список у БД. Порожній список справді очищає каталог. Не відкривайте одночасно кілька редакторських вікон: наразі немає захисту від конкурентного перезапису.
5. Оновіть «Події міста» у мобільному застосунку.

Неопубліковані зміни живуть лише у вкладці. При виході є попередження, але немає серверних чернеток/історії версій. Ключ не зберігається у браузері та не передається в URL. JSON-редактор залишено як розширений режим і для перевірених зборів. Після зміни JSON спочатку застосуйте його до списку змін, потім опублікуйте.

### Якщо не відкривається або не завантажує

- `/admin/` повертає 404, але `/admin/index.html` працює — запущений код без нового маршруту. Використайте повну адресу або перезберіть і перезапустіть сервер.
- 503 під час завантаження — на сервері не заданий EDITORIAL_ADMIN_KEY. Додайте власний довгий випадковий ключ у backend/.env; після зміни потрібен перезапуск.
- 401 — ключ неправильний.
- 502 — недоступне початкове джерело карти. Спробуйте імпорт пізніше; це не помилка ключа, й наявні точки не замінюються порожнім списком.
- 400 для нових категорій — перевірте поля й переконайтеся, що бекенд перезібрано з розширеним валідатором.

Для локального показу відкривайте редактор на комп’ютері. Не публікуйте адміністративний доступ в інтернет без HTTPS, облікових записів працівників, ролей та журналу змін.

## Формат події

```json
{
  "items": [
    {
      "id": "event-2026-10-01",
      "title": "Назва події",
      "date": "2026-10-01",
      "time": "18:00",
      "venue": "Місце проведення",
      "address": "Ужгород, адреса місця проведення",
      "category": "Концерти",
      "description": "Короткий перевірений опис події.",
      "sourceUrl": "https://organizer.example/event",
      "verifiedAt": "2026-10-08"
    }
  ]
}
```

Для подій обовʼязкова повна дата з роком: старі day/dateLabel більше не використовуються. Категорії: Концерти, Театр, Виставки, Лекції та зустрічі, Майстер-класи, Спорт, Для дітей, Фестивалі, Інше. Додаткові поля: posterUrl (HTTPS), organizer, address, time (HH:mm). Події можуть бути безкоштовними: sourceUrl веде на інформацію або реєстрацію, а не обов’язково на продаж квитків.

Адмінка зараз охоплює події, перевірені збори, укриття та пункти незламності. Для опитувань і ЦНАП потрібні окремі моделі/API. Дані погоди, GPS, тривог та офіційних новин не підміняються ручними записами.

## Укриття та пункти незламності

1. Перезберіть і перезапустіть бекенд. Виберіть відповідний розділ, введіть той самий EDITORIAL_ADMIN_KEY і натисніть «Завантажити дані».
2. До першої публікації імпортуються поточні точки карти: укриття з геопорталу (з чинними ручними поправками), пункти незламності з наявного локального переліку. Імпорт сам не записує БД. При недоступному джерелі помилка не маскується порожнім списком — спробуйте пізніше. Порожній наявний перелік пунктів можна наповнювати з нуля.
3. Знайдіть об’єкт за назвою/адресою, натисніть «Редагувати» або «Додати укриття / пункт незламності». Заповніть назву, повну адресу, координати точного входу (широта 48…, довгота 22…). Крапка або кома приймаються. Кнопка карти відкриває введену точку для перевірки, без автоматичного геокодування.
4. За потреби додайте опис входу, публічне HTTPS-джерело й справжню дату перевірки. Дата не заповнюється автоматично; майбутні/неможливі дати не приймаються. Публікація не означає, що вхід відкритий чи об’єкт безпечний.
5. «Додати до списку змін» створює лише чернетку. «Опублікувати зміни» з окремим діалогом зберігає весь перелік у PostgreSQL. Видалення теж набирає чинності лише після публікації. Порожній опублікований список прибирає всі точки цього розділу; не замінюється автоматичним джерелом.
6. В застосунку відкрийте відповідну карту або натисніть оновлення. Мітка показує адресу, опис, дату та посилання. Сервер читає редакторський список на кожен запит, без очікування TTL геопорталу.

Після першої публікації редакторський список повністю замінює автоматичне джерело саме цього розділу. Нові точки геопорталу не додаються автоматично: надалі підтримуйте цей каталог вручну. Це явно позначено в адмінці та застосунку. Старий растровий шар укриттів у редакторському режимі прихований, щоб видалені точки не залишались намальованими на тайлах. Два списки незалежні. Сервер і клієнт перевіряють координати в межах Ужгорода та унікальність ID. Реальні адреси/точки в цьому проході не вигадували й не публікували.

## Формат перевіреного збору

```json
{
  "items": [
    {
      "id": "fund-2026-10",
      "title": "Назва збору",
      "description": "Коротко: на що збір.",
      "donationUrl": "https://send.monobank.ua/jar/...",
      "verifiedAt": "2026-10-01",
      "verificationSource": "Посилання на офіційне підтвердження"
    }
  ]
}
```

## Як це виглядатиме для міста

На демонстрації достатньо сказати: працівник відкриває закритий редактор, додає подію або перевірений збір, перевіряє дату й джерело, натискає «опублікувати», а застосунок отримує нові дані з API. Для пілоту це один ключ редактора; у міській версії наступним кроком буде вхід працівників, ролі «редактор / модератор / адміністратор» та журнал усіх змін.
