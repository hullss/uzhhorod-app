# Uzhhorod Digital API

## Вебдемо та CORS

API дозволяє лише точні браузерні origins із `app.cors.allowed-origins`.
За замовчуванням це `localhost` і `127.0.0.1` на портах 8081, 8083 та 8084.
Для іншого порту або опублікованого демо задайте `WEB_ALLOWED_ORIGINS` у
`backend/.env`: список через кому, зі схемою та портом, без шляху й кінцевого `/`.
Наприклад: `WEB_ALLOWED_ORIGINS=http://localhost:8083,https://demo.example.org`.
`*` та origin `null` заборонені. Cookies між сайтами не дозволені; акаунти
використовують Bearer-токен. Авторизація endpoint-ів залишається обов'язковою.

Потрібно перебудувати й перезапустити **той сервер**, який указано в
`mobile/.env` як `EXPO_PUBLIC_API_URL`. Зміна локального коду сама по собі не
оновлює віддалений сервер. Перезапуск Expo не додає CORS-заголовків.
Після зміни адреси API в `mobile/.env` також перезапустіть Expo.

Перевірка після перезапуску:

```powershell
curl.exe -i -H "Origin: http://localhost:8083" http://localhost:8080/api/transport/status
```

Очікується `Access-Control-Allow-Origin: http://localhost:8083`. Якщо API
віддалений — підставте його адресу замість `localhost:8080`. HTTPS-вебдемо
має використовувати HTTPS API або спільний origin: CORS не виправляє mixed content.

## WeatherAPI

Погода працює через серверний ключ WeatherAPI — він ніколи не передається в мобільний застосунок.

Перед запуском бекенду створіть файл `backend/.env` за зразком `backend/.env.example` і додайте ключ, отриманий у WeatherAPI:

```env
WEATHER_API_KEY=ваш_ключ
ALERTS_IN_UA_TOKEN=ваш_токен_з_alerts.in.ua
```

Після зміни `.env` перезапустіть бекенд:

```powershell
.\mvnw.cmd spring-boot:run
```

Після запуску доступний endpoint `GET /api/city-services/weather`. Відповідь кешується на 15 хвилин.

## Офіційні новини

`GET /api/city-services/news` раз на 10 хвилин читає головну сторінку Ужгородської міської ради. У відповідь потрапляють лише заголовок, дата та посилання на оригінал — повні тексти і фото не копіюються.

## Живе місцезнаходження автобусів

`GET /api/transport/vehicles?routeNumber=2` є серверним адаптером до офіційного JSON-ресурсу DozoR, який оприлюднений Відділом транспорту на порталі відкритих даних. Бекенд перевіряє відповідь кожні 20 секунд, не передає в мобільний застосунок IMEI чи інші технічні ідентифікатори трекера та повертає `available: false`, якщо джерело тимчасово не відповідає.

Посилання на джерело вже задано в `application.yml`. За потреби його можна замінити без правки коду у `backend/.env`:

```env
TRANSPORT_REALTIME_SOURCE_URL=https://city.dozor.tech/data
TRANSPORT_REALTIME_CACHE_DURATION=PT20S
```

Після зміни `.env` перезапустіть бекенд. Прогноз прибуття на зупинку поки залишається плановим GTFS-розкладом: GPS-ресурс треба окремо перевірити на стабільну підтримку прогнозів прибуття, перш ніж називати такий час фактичним.

`fetchedAt` означає час отримання відповіді від DozoR. `measuredAt` повертається
як `null`, доки адаптер не має перевіреного часу GPS-виміру від джерела.
Свіжа HTTP-відповідь не є гарантією свіжого GPS-виміру. На карті показано
«Позиції з DozoR» та час отримання; планові відправлення не називаються GPS-прогнозом.
