# Uzhhorod Digital API

## WeatherAPI

Погода працює через серверний ключ WeatherAPI — він ніколи не передається в мобільний застосунок.

Перед запуском бекенду створіть файл `backend/.env` за зразком `backend/.env.example` і додайте ключ, отриманий у WeatherAPI:

```env
WEATHER_API_KEY=ваш_ключ
ALERTS_IN_UA_TOKEN=ваш_токен_з_alerts.in.ua
```

Після зміни `.env` перезапустіть бекенд:

```powershell
.\mvnw.cmd spring-boot:run
```

Після запуску доступний endpoint `GET /api/city-services/weather`. Відповідь кешується на 15 хвилин.

## Офіційні новини

`GET /api/city-services/news` раз на 10 хвилин читає головну сторінку Ужгородської міської ради. У відповідь потрапляють лише заголовок, дата та посилання на оригінал — повні тексти і фото не копіюються.

## Живе місцезнаходження автобусів

`GET /api/transport/vehicles?routeNumber=2` є серверним адаптером до офіційного JSON-ресурсу DozoR, який оприлюднений Відділом транспорту на порталі відкритих даних. Бекенд перевіряє відповідь кожні 20 секунд, не передає в мобільний застосунок IMEI чи інші технічні ідентифікатори трекера та повертає `available: false`, якщо джерело тимчасово не відповідає.

Посилання на джерело вже задано в `application.yml`. За потреби його можна замінити без правки коду у `backend/.env`:

```env
TRANSPORT_REALTIME_SOURCE_URL=https://city.dozor.tech/data
TRANSPORT_REALTIME_CACHE_DURATION=PT20S
```

Після зміни `.env` перезапустіть бекенд. Прогноз прибуття на зупинку поки залишається плановим GTFS-розкладом: GPS-ресурс треба окремо перевірити на стабільну підтримку прогнозів прибуття, перш ніж називати такий час фактичним.
